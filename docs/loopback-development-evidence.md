The r01 failure is useful controller evidence: neither arm requested public tests during generation, repeated reads consumed the fixed action budget, and repairs were incomplete across files. It does not establish a weights limit. The new preview adds automatic public review and returns a small exact current source span for an explicitly repeated read.

The live r03 diagnostic produced a changed patch and a real public test receipt,
then correctly withheld acceptance. Its prompt path spent 286.119 seconds on
prefill and 27.123 seconds on decoding, with 55,148 input and 682 output tokens.
Detailed public failure feedback was available in the journal but could be
rotated out of the prompt while its summary retained only the failed status.
That observed gap motivates the optional source-bound feedback extension. Ten
offline checks passed; a further private spent diagnostic is in progress. Its
live effect is not reported yet and transfer claims require a separate experiment.

The native hourly r02 feed is verified and enabled on a shared native-visible C
control root. Stop and Start were tested, and 82 local cloud-mount files were
read back on each configured destination. These controls do not start models.
Remote provider upload remains unproven.

The [sanitized snapshot](../evidence/loopback-2026-10-08.json) records full source
and evidence hashes, test scope, observable outcomes and missing measurements.
The [preview's historical acceptance detail](../lab/accuracy_preview/EVIDENCE.md)
records earlier source and contract checks; it does not supersede the failed r03
acceptance or establish a later coding result.

The worker was still running when SSH stopped completing its banner. ACPI shutdown did not complete; only that owned emulator was stopped through QMP and restarted. Read-only kernel and Docker health checks then passed, and the original guest profiles were restored. The interrupted action remains recorded as uncertain; the six frozen predictions were preserved.

The current calibration used the same Qwen3.5-4B Q4_K_M weights and a pinned llama.cpp Vulkan runtime. The configuration uses an 8,192-token context, one slot, a 1,300-token generation reserve, q8_0 K/V, flash attention and ngram-simple. Cross-task prompt reuse was disabled for the comparison. The model's 33/33 layers were offloaded to the laptop's Intel graphics. This is a measured Vulkan configuration, not a CUDA performance claim.

No official SWE-bench Verified 50 model score is published here. The official evaluator's gold-patch canary establishes infrastructure readiness only; it is not a model solve.

Each evidence receipt records full SHA-256 identities, observable outcomes and unknowns. Hashes establish byte identity against a supplied pin; independent replay and evaluation remain necessary for stronger claims.
